## A Probabilistic RoadMap (PRM) simulator in ROS.

_Planning a path from the robot's position to multiple goal locations._

## Introduction
### Rationale

A probabilistic roadmap planner is a common motion-planning algorithm used in robotics. In taking random samples from the free space surrounding a robot, the algorithm attempts to connect configurations (groups of samples) to capture the connectivity of the overall environment. Shortest path finding algorithms (such as Dijkstra) may then be used to find a path between a start and end goal.

### Low Dispersion Probabilistic Roadmaps

This implementation uses LD-PRM planning. The idea behind LD-PRM is to capture the connectivity of the configuration space with fewer samples, reducing the overall running time of the algorithm. Different to a simple PRM planner, the samples generated by the LD-PRM must fulfil an important criterion in order to be included on the roadmap. This constraint can be thought of as a 'separation distance' - new samples are forbidden to be within a certain distance of other samples already on the roadmap.

This criterion helps create an almost uniform distribution of samples across the free configuration space. As the PRM network increases in size, this separation distance decreases, and the network better captures the entire form of the known environment. This also helps the planner navigate narrow passages, which present significant challenges in other PRM implementations.

> Khaksar, W. Hong, T. Khaksar, M. Motlagh, O. 2013, "A Low Dispersion Probabilistic Roadmaps (LD-PRM) Algorithm for Fast and Efficient Sampling-Based Motion Planning", International Journal of Advanced Robotic Systems, Vol.10, [Link](http://cdn.intechopen.com/pdfs/45913.pdf)

## Installation
### Required Packages

The Probabilistic Roadmap simulator has been tested on Ubuntu 14.04 / ROS Indigo and Ubuntu 16.04 / ROS Kinetic.

ROS Indigo:
```bash
$ sudo apt-get install ros-indigo-local-map ros-indigo-stage-ros ros-indigo-rosdoc-lite
```
ROS Kinetic:
```bash
$ sudo apt-get install ros-kinetic-stage-ros ros-kinetic-rosdoc-lite
```
For Kinetic users, they must install `local_map` from source as it is not part of the standard kinetic repositories. You can find the docs and source location for `local_map` [here](http://wiki.ros.org/local_map).

### Building

This project uses `catkin` and `CMake` to build it. After placing the project in the src directory of the catkin workspace `catkin_ws/src/prm_sim`, run `catkin_make -j1` (in the catkin workspace) to auto-generate src from the srv file.

After that initial build, calls to `catkin_make` will suffice.

### Testing

This project also comes with a series of unit tests that are run on a gtest framework. To build these tests run `catkin_make tests` from the catkin workspace. To run these tests simply execute the following in `catkin_ws`:
```bash
$ ./devel/lib/prm_sim/prm_sim-test
```

It is important to note that due to the non-deterministic behaviour of prm network building, there is a chance some of the unit tests could fail. To visualise the generation of the prm networks during unit testing, pass `--show` as a command line argument. To increase or decrease the amount of prm building rounds (default is ten) during unit testing, pass `-t <max_rounds>` as a command line argument.

For example if we wanted to show the building of the prm network for 3 rounds at most, we would run:

```bash
$ ./devel/lib/prm_sim/prm_sim-test --show -t 3
```

## Operation
### Starting ROS

First and foremost, `roscore` must be started to service all the various ros nodes:
```bash
$ roscore
...
```
Next, start the world stage which will allow you to click and drag the position of the robot within the map:
```bash
$ rosrun stage_ros stageros $(rospack find prm_sim)/worlds/uoa_robotics_lab.world
[ INFO] [1508799387.191771549]: Found 2 laser devices and 0 cameras in robot 0
[ WARN] [1508799387.298406431]: ROS Stage currently supports rangers with 1 sensor only.
...
```
Next, start the `local_map` node, which converts the world map above into an ogMap:
```bash
$ rosrun local_map local_map /local_map/scan:=/base_scan_1 _map_width:=200 _map_height:=200 _map_resolution:=0.1
[ INFO] [1508799528.068394858, 0.200000000]: Found world frame odom
...
```
Next start the `map_to_image` node which coverts ogMaps to openCV images:
```bash
$ rosrun prm_sim prm_sim_image_node map:=/local_map/local_map /pose:=/odom
[ INFO] [1508799607.900065056]: Map to Image node started.
...
```
Finally, and most importantly - start the prm simulator by running:
```bash
$ rosrun prm_sim prm_sim_node
[ INFO] [1508799676.104498061]: Init with: map_size={20.0} resolution={0.1} robot_diameter={0.2} density={5}
...
```

If one wishes to run the simulator with default values, the `start.sh` script will execute all the above commands for convenience.

### Visualisation

One might want to additionally visualise the produced prm network and the robot's configuration space. To do so, the following commands can be additionally run.

Visualisation of robot pose, map space and line of sight:
```bash
$ rosrun rviz rviz -d $(rospack find prm_sim)/rviz/pfms.rviz
```
Visualisation of the prm network and path (looking at topic `/prm`):
```bash
$ rqt_image_view
```

### Requesting goals

Once all the relevant ROS nodes have been started, one can start requesting goals for the simulator to plan a path towards. This achieved by posting messages on the ros service `/request_goal`. For example if I wanted to plan a path between the robot's current position and the map coordinates `(x=2.7, y=3.1)`, I would execute:
```bash
$ rosservice call /request_goal -- 2.7 3.1
```
When requesting a goal, x and y coordinates are rounded to one decimal place. Note that goals outside of the configuration space, or in unknown areas, will be dumped. To see if a path was successfully planned, check the logs produced by `prm_sim_node`. For example, a successful path plan may look like this:

## Robot Path Planning with ROS 2 and PRM (2026 Edition)


The original project documentation was written for **ROS 1 (Indigo/Kinetic)**, which is now completely obsolete. Modern robotics uses **ROS 2** (specifically modern long-term support versions like **ROS 2 Humble, Iron, or Jazzy**). 

This translates those outdated concepts into modern 2026 ROS 2 practices using simple analogies, visual models, and Python.

---

## 1. Core Concepts: 

Before writing code, let's understand exactly what a **Probabilistic RoadMap (PRM)** planner does using a real-world story.

### What is a PRM? (The "Connect-the-Dots" Analogy)
Imagine you are locked in a massive, dark furniture warehouse. You want to get from the front entrance to the back exit, but you don't have a map of where the couches and tables are. 

How could you find a path?
1. **Take Random Samples:** You throw 500 glowing pebbles blindly into the air. They land all over the floor. 
2. **Clear the Obstacles:** You walk around and pick up any pebble that accidentally landed *on top* of a couch or inside a wall. Now, you only have pebbles resting safely on the open, walk-able floor.
3. **Connect Neighbors:** You walk to each pebble and draw a chalk line to any other nearby pebble, *as long as there isn't a piece of furniture blocking the line*. 
4. **Solve the Maze:** Suddenly, you have a giant connected network of chalk lines across the warehouse. You can easily follow the lines from the entrance to the exit!

This is exactly what a **PRM** does. The "pebbles" are **Nodes** and the "chalk lines" are **Edges**.



### What is Low-Dispersion PRM (LD-PRM)?
In a standard PRM, random throwing means 5 pebbles might land right on top of each other in a tight cluster. This wastes time and resources. 

**Low-Dispersion** simply adds one rule: *"Before a pebble is allowed to stay on the floor, check if there is already another pebble within 2 feet of it. If there is, throw it away and try somewhere else."* This single rule forces the pebbles to spread out beautifully and evenly across the entire room, allowing the robot to discover tiny, narrow doorways it might have otherwise missed.

## 2. Robot Operating System-2 -- Info flow.

Imagine a robot as a bustling restaurant crew:
* **The Camera/Laser Sensor** is the *Busboy* yelling: *"There's a wall over here!"*
* **The PRM Brain** is the *Head Chef* mapping out a path.
* **The Wheels** are the *Delivery Drivers* waiting for orders.

In ROS 2, every individual program is called a **Node**. Nodes pass notes to each other using **Topics** (radio channels) and **Services** (direct question-and-answer phones).

## 3. Modern ROS 2 Architecture

In old ROS 1, you had to manually launch a server called `roscore`. In **ROS 2**, `roscore` is gone! Nodes discover each other automatically across your network safely and instantly. 

We build and run modern ROS 2 workspaces using a build tool named **`colcon`** instead of the old `catkin`.

## 4. Creating a ROS 2 PRM Planner Node

Python code using **`rclpy`** (the official ROS 2 Python library). It creates a single ROS 2 Node that simulates generating random "pebbles" (samples), applies the Low-Dispersion rule, and serves that path when requested.

### How to read this code:
* `__init__`: Sets up our ROS 2 Node and opens up a **Service** phone line called `/request_goal`.
* `generate_roadmap`: Throws the random pebbles into our map space.
* `handle_goal_request`: Triggers automatically when someone calls our service phone line asking for a path.

--- 
---

```python
#!/usr/bin/env python3
import random
import math
import rclpy
from rclpy.node import Node
from std_srvs.srv import Trigger # A simple standard ROS 2 question/answer service

class ProbabilisticRoadmapNode(Node):
    def __init__(self):
        # Initialize our ROS 2 Node and name it 'prm_simulator'
        super().__init__('prm_simulator')
        
        self.get_logger().info("Initializing ROS 2 PRM Simulator Node (2026 Edition)...")
        
        # Configuration Settings for our "Warehouse Floor"
        self.map_width = 20.0   # 20 meters wide
        self.map_height = 20.0  # 20 meters high
        self.min_separation = 2.0 # LD-PRM Rule: Pebbles must be at least 2 meters apart!
        
        # This list will hold our valid map points (the roadmap)
        self.roadmap_nodes = []
        
        # Step 1: Run our Low-Dispersion sampling algorithm
        self.generate_roadmap(num_samples=100)
        
        # Step 2: Create a ROS 2 Service phone line. 
        # Anyone can call '/request_goal' to trigger path generation!
        self.srv = self.create_service(Trigger, 'request_goal', self.handle_goal_request)
        self.get_logger().info("Service line '/request_goal' is now OPEN and active.")

    def generate_roadmap(self, num_samples):
        self.get_logger().info(f"Generating roadmap using Low-Dispersion constraints...")
        
        attempts = 0
        while len(self.roadmap_nodes) < num_samples and attempts < 1000:
            attempts += 1
            
            # Generate a random coordinate on our 2D floor grid
            sample_x = random.uniform(0.0, self.map_width)
            sample_y = random.uniform(0.0, self.map_height)
            
            # Low-Dispersion check: Is this new point too close to any existing point?
            too_close = False
            for (nx, ny) in self.roadmap_nodes:
                # Calculate simple physical distance between two points
                distance = math.sqrt((sample_x - nx)**2 + (sample_y - ny)**2)
                if distance < self.min_separation:
                    too_close = True
                    break # Stop checking, this point is disqualified!
            
            # If it passed the distance constraint test, save it to our roadmap!
            if not too_close:
                self.roadmap_nodes.append((sample_x, sample_y))
                
        self.get_logger().info(f"Successfully placed {len(self.roadmap_nodes)} well-spaced nodes after {attempts} attempts.")

    def handle_goal_request(self, request, response):
        """ This function runs automatically whenever another ROS 2 node calls our service """
        self.get_logger().info("Goal request received via ROS 2 Service!")
        
        # Pick a random node from our map to simulate a successful path target
        if self.roadmap_nodes:
            target = random.choice(self.roadmap_nodes)
            response.success = True
            response.message = f"Path successfully planned to coordinates: X={target[0]:.2f}, Y={target[1]:.2f}"
        else:
            response.success = False
            response.message = "Roadmap is empty. Could not plan a path."
            
        return response

def main(args=None):
    # Initialize the global ROS 2 communication framework
    rclpy.init(args=args)
    
    # Spin up our node
    node = ProbabilisticRoadmapNode()
    
    try:
        # Keep the program alive, listening for incoming service calls
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.get_logger().info("Shutting down PRM Simulator Node gracefully.")
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()

```

## 5. Step-by-Step Execution Guide 

To build and run this modern simulator code package on a computer with ROS 2 installed, you use clean workspace commands.

### Step 1: Create Your Workspace Directory

Open your Linux terminal and create your project folder setup:

```bash
$mkdir -p ~/ros2_ws/src/prm_sim$ cd ~/ros2_ws/src/prm_sim

```

### Step 2: Build the Workspace using `colcon`

Go back to your workspace root directory and ask ROS 2 to compile your files:

```bash
$cd ~/ros2_ws$ colcon build --symlink-install

```

> **Note for dev:** `--symlink-install` is an awesome shortcut command. It means every time you change your Python code file, you don't have to rebuild the project! Your changes apply instantly.

### Step 3: Source the Environment

You must tell your terminal tab where your newly compiled custom ROS 2 programs live:

```bash
$ source install/setup.bash

```

### Step 4: Run the PRM Node

Now, execute your simulator node program directly:

```bash
$ ros2 run prm_sim prm_sim_node

```

You will immediately see the initialization confirmation logs appear on your screen tracking how the random coordinates are being laid out.

### Step 5: Test and Request a Goal via Terminal Call

Open a **brand-new terminal window** tab, jump inside your workspace directory, source it again, and run a command-line service call to request a coordinate objective:

```bash
$cd ~/ros2_ws$ source install/setup.bash
$ ros2 service call /request_goal std_srvs/srv/Trigger

```

Your simulator node will intercept the command, run its calculation, and print out a response showing the planned location route immediately:

```
response: std_srvs.srv.Trigger_Response(success=True, message='Path successfully planned to coordinates: X=14.32, Y=8.75')

```
